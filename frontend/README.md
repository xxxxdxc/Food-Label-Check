# 食品包装预审工作台

声称模型初审已接入后端共享契约，使用既有VLM API的 `gpt-6.1-sol`。结果页对未覆盖声称独立展示初审意见、原因、参考依据和缺失材料，支持版本校验、排队轮询及显式批次重试。读取和刷新不触发模型调用，初审不改变规则结论和人工标签。缺少claim_id的历史检查项只能手动查看本版本批次，不按文案猜配。方案及后端约定见 [交接文档](./BACKEND_HANDOFF_CLAIM_PRECHECK.md)。

当前版本直接连接真实 API，打开即进入工作台，无需共享口令。仅供本机使用，已移除登录页、虚构数据适配器和内置样本入口。

## 当前识别流程

新上传采用 `VLM 分区 → 区域裁剪 → OCR → 自动校验 → 规则检查`。VLM 仅返回区域类别及坐标，不转录文字或数值，也不生成与 OCR 的对比候选。普通文字区域调用一次高精度 OCR；营养表区域使用高精度 OCR 提供置信度、Table V2 提供行列结构。重叠区域会合并，表格内部的重复文字区域共用表格 OCR。

分区超时、无效或不完整时降级为整图 OCR，并展示警告；不再调用 VLM 做字段转录兜底。字段置信度≥96%且格式/单位校验通过即可自动放行，结构正常的表直接进入规则检查；结构异常单独作为表级问题，低置信、无法解析、单位不符或冲突字段保持人工复核。缺失可信度不能当作高可信。

分区计划和 OCR 原始响应按流水线版本、图像/裁剪指纹缓存，坐标回映到上传原图。分区后的实际 OCR 调用数会检查每日剩余额度；区域较多时调用数可能增加。旧任务的文档、候选和复核历史保持原样，不自动重跑。所有任务统一隐藏旧双路比较、视觉候选和一致项批量确认，展示当前识别记录与原图核对入口。

复核页和结果页提供默认折叠的“识别区域与处理说明”，按图片展示区域类别或整图 OCR 降级提示。分区框默认隐藏，可开关或点击区域定位；框不填色，独立于 OCR 证据标记。后端未提供子阶段进度，因此只按排队、分区与识别、规则检查展示实际任务状态。

营养表使用同版本字段和复核队列生成唯一编辑区，取消同表的逐字段卡片和第二份只读预览。表内直接修改待核单元格，数值与行列关系只勾选一次确认，未提交修改立即反映在当前草稿。OCR 原文、可信度和原因默认收起，可展开查看和定位原图。基础信息仍使用独立卡片。

正常修正将本表待核字段决策与一次表级确认合并到同一请求；“调整行结构”带入当前草稿，在同一张表增删行或补录空格，提交时只发送整表替换，不混发同表字段决策。按图片分组提交，并保留版本冲突和保存后回读检查。读取失败、版本不符或字段与表不能可靠对应时保留独立入口，不推测绑定；重复营养项按行保留，不能按名称去重。

当前后端的 `confirm_complete` 只接受 `needs_review` 诊断，而现有恢复任务的 `TABLE_LAYOUT_RECOVERED` 仍为 `needs_vision`。若直接确认因此被拒，页面保留草稿并说明使用同区“调整行结构”的整表替换路径。本次未改后端门禁，也未替用户提交真实任务。

手动整表录入的含量与 NRV% 仅接受非负纯数字；例如 NRV% 输入 `10`，不接受 `10%` 或 `10％`，不会自动删除符号或转换输入。错误按行关联到对应输入框，提交栏说明所选数据的格式错误、未勾选核对或缺少复核人等拦截原因。整表录入会替换当前整表，确认前需保留全部真实营养项；切换基准不自动换算含量。原始表头可在识别依据中查看。

净含量候选若明确与 OCR 原文中的标准号或许可证编号一致，且无同值的显式净含量标签，会显示字段错配警告；该候选不默认填入确认框，也不能通过“恢复当前值”带回。原始 OCR 记录保持不变。净含量需人工填写纯数字、按原图选择单位后才能勾选；不自动补单位、不从每份质量推算、不用数值大小判断真假。含有明确同值净含量标签的正常记录仍保留。该防护不代替后端字段提取修复，详见 [后端交接说明](./BACKEND_HANDOFF_NET_CONTENT.md)。

## 本对话职责边界

本对话仅修改 `frontend/`。后端代码、共享契约、运行数据与服务进程只读核对；涉及这些范围的修改或服务操作，必须先提醒用户超出前端职责。

收到问题反馈后，先只读排查并提出方案，经用户明确审核通过后再修改和验证；反馈本身不视为实施授权。

## 启动真实工作台

前端已构建，仓库根目录运行：

```powershell
.\start-local.ps1
```

访问 http://127.0.0.1:5182/ 。脚本以隐藏窗口启动 API 和独立 Worker，统一使用 `src/.env` 中的已有配置，固定 `LOCAL_ONLY=1`、`OCR_MODE=live`、`VLM_ENABLED=1`，API 只监听 `127.0.0.1` 并关闭代理头信任。API 同时托管生产前端，无需启动 Vite。端口占用时脚本拒绝重复启动。

上传同一商品的 PNG/JPG 包装图（最多三张、单张 10MB），点击“开始审核”后才实际调用识别服务。错误展示真实原因，不回退假数据。识别后的待复核数据、规则结果和报告来自后端，任务历史持久保存在 `src/data`。保留后端原有缓存样本接口供开发回归使用，页面不提供该入口。

运行日志与启动进程编号保存在 `src/data/local-runtime/`（不提交）。Worker 必须持续运行，否则新建任务将停在排队状态。当前已启动的服务无需再次运行启动脚本。

## 前端开发

```powershell
npm ci
npm run dev
```

开发服务器默认只监听 `127.0.0.1:5182`，`/api` 和 `/openapi.json` 代理到 `127.0.0.1:8000`，保留 Host 以兼容 Origin 校验。开发时需另行在 8000 启动 API 和独立 Worker，并停止占用 5182 的生产服务，或为 Vite 指定其他端口。

## 构建与检查

```powershell
npm run gen:types
npm run typecheck
npm run build
npm run test:e2e
```

类型来自 `shared/openapi.json`，生产文件输出到 `dist/`。`test:e2e` 默认连接已启动的本机服务，非默认 Chrome 路径可设置 `$env:CHROME_PATH='C:\Program Files\Google\Chrome\Application\chrome.exe'`，非默认服务地址设置 `TEST_BASE_URL`。

浏览器检查仅提交无法解码的测试文件，验证本地拒绝和不创建任务，不发送有效包装图或触发 OCR / VLM。测试覆盖免登录入口、旧登录地址跳转、样本入口移除、上传校验、API 错误原样展示及桌面/375px布局。真实图像识别由用户上传验收。

详见 [VALIDATION.md](./VALIDATION.md)。

## 离线全链路回归（开发专用）

```powershell
$env:CHROME_PATH='C:\Program Files\Google\Chrome\Application\chrome.exe'
npm run test:offline
```

使用已有的 `src/.venv/Scripts/python.exe`（需已安装后端 requirements）；其他 Python 路径可通过 `OFFLINE_TEST_PYTHON` 指定。命令构建当前前端，在独立的 127.0.0.1:5193 启动测试 API 和队列消费线程，结束后停止。每次创建 `src/data/test-runtime/browser-*` 隔离目录，不连接正在使用的数据库，不修改 `.env`。

只有测试提取器使用明确的合成识别记录，OCR/VLM 方法被禁止调用；真实上传校验、SQLite 持久化、人工修正、规则计算、标记/撤销和报告接口仍完整执行。这验证接口和交互衔接，不证明真实图片识别准确率。该测试服务仅用于开发回归，不能作为用户工作台启动。
