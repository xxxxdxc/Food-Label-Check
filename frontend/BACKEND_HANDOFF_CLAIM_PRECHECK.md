## 已确认范围

- 仅对固定规则未覆盖且文字已确认的声称初审。高蛋白、低糖等已覆盖项继续由引擎计算，不重复调用模型。
- 输入为现有包装图片、已确认OCR、审核过的旧references。模型输出独立展示，不改L1结论、每100g NRV计算、人工标签或任务放行。
- 输出“有材料支持／发现矛盾／材料不足”，附理由、引用及缺失材料。缺材料不代表违规，不默认要求修改包装。
- 不新增材料上传、不自动联网检索、不扩充企业或渠道规则引擎。
- 用户指定：通过现有VLM API通道调用 `gpt-6.1sol`。

## API和模型

复用既有VLM API的base URL、凭据获取方式及调用计数，不新增供应商通道，不在文档或前端暴露密钥。

`gpt-6.1sol` 是用户指定的模型标识，本轮未探测API，尚未验证网关接受的精确model字符串。后端实施时核实同一网关的部署标识并记录映射；不可用时报告配置错误，不静默换模型。记录实际请求及返回的模型标识。

建议为声称初审设置独立model配置（配置名由后端确定），使用核实后的上述ID。不要直接覆盖既有分区模型配置。当前 `src/app/services/zoning.py::propose_regions` 明确只做分区，禁止转录值和审核结论；保持此约束，另建初审服务、提示词和返回Schema。复用API通道不等于复用分区响应，不重新执行OCR。

## 建议执行流程（待后端实现）

1. 消费当前已确认声称及其原图证据；未确认文字留在既有OCR复核流程，不由模型替代转录。
2. 按现有规则匹配识别未覆盖项，不能只靠前端文本猜测。同一文档版本的未覆盖项批量初审，逐项返回。
3. 输入包括声称ID、类别和原文、图片与证据ID、相关确认数据，以及准入资料片段和ID。输入文字作为数据，不执行图片或参考资料里的指令。
4. 校验模型结构和引用，只接受输入中存在的资料、证据引用；不自造条款或定位框。缺产品事实依据应输出材料不足；有材料支持不等于最终合规签核。
5. 独立异步处理，不阻塞确定性检查，不新增或改变现有任务状态。超时、额度不足或模型不可用只令初审暂不可用，不新增违规或把任务改成FAILED。
6. 以文档版本、图片/确认数据、资料清单、实际模型及提示词版本组成缓存指纹，去重调用。GET和刷新不触发付费重试；旧意见不得冒充新版本结果。不自动重跑历史任务。

## 接口草案：不是现有API

建议独立只读接口：`GET /api/audits/{id}/claim-prechecks?version=<document_version>`。
具体任务触发、路由和字段由后端确认后更新共享OpenAPI，再生成前端类型。本轮不改共享契约。

```json
{
  "document_version": 1,
  "schema_version": "claim-precheck-v1",
  "status": "completed",
  "items": [{
    "claim_id": "<当前文档声称ID>",
    "claim_text": "非油炸",
    "claim_category": "process",
    "source_evidence_refs": ["<该声称原文证据ID>"],
    "status": "completed",
    "verdict": "insufficient_evidence",
    "reason": "现有包装和参考资料不足以核实生产工艺。",
    "supporting_evidence_refs": [],
    "reference_citations": [],
    "missing_materials": ["能够证明该产品生产工艺的材料"],
    "model_requested": "gpt-6.1sol",
    "model_actual": "<API实际返回标识>",
    "reference_set_version": "<审核资料清单版本>",
    "prompt_version": "claim-precheck-v1"
  }]
}
```

- 顶层及单项status：`pending / running / completed / unavailable`。无未覆盖项返回completed和空items，不调用模型。
- verdict仅在completed时有效：`supported / contradiction / insufficient_evidence`，其他状态为空；不要以材料不足掩盖API失败。
- reference_citations每条含准入资料ID、标题、来源类型、文件/章节及相关片段。模型/资料/提示词版本放追溯详情，不占主要操作区。
- 使用声称ID与文档版本关联；不要用可能重复的CLAIM-UNKNOWN计数ID或仅凭文字做唯一绑定。
- 示例仅说明契约及预期语义，不是真实模型输出，不表示资料审核或产品工艺核验已完成。

## 前端展示约定（待契约就绪）

- 在对应未覆盖声称详情独立展示“模型初审”：原文、初审结论、简短原因、引用依据、缺失材料及原文定位。
- 解释为“已识别，暂未被固定规则覆盖”；不把整表OCR当作该声称的直接证据，不暗示文字没识别或已违规。
- 模型意见不进入原有规则结论统计，不自动将规则改成PASS，不自动写“确认问题／误报”。这些仍是人工处理意见。
- 不显示空计算过程；无确定规则依据时说明当前规则未覆盖，不用通用“条款待确认”和“请修正”暗示已有违规依据。
- 等待中、暂不可用、材料不足分别显示。无接口时不伪造初审；版本不一致标记过期。

## 验收

- 已覆盖项零新增调用；同版本未覆盖批次去重，刷新不重复扣费。验证请求走既有VLM API和核实后的gpt-6.1sol部署ID，不影响分区模型。
- 非油炸仅有包装自述、无工艺材料时为材料不足。旧经验不能当真实性证明；支持或矛盾必须有可追溯输入依据。
- 坏JSON、自造引用、文档版本不符不接受为有效意见。原始OCR、人工记录和模型意见分别保留。

- 隔离响应只能验证流程；真实API验收另记实际模型、调用量和效果，不以隔离测试冒充模型效果验证。
